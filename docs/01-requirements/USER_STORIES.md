# 用户故事与 BDD 验收标准

> 文档版本：v1.0  
> 适用范围：广告制作公司宣传物料订单管理系统 MVP  
> 编写规范：BDD / Gherkin Given-When-Then  
> 场景数量：每故事 3 组（1 主干正常流 + 2 边界异常流）

---

## US-001 · 客户经理登记新订单

**用户故事：**
> 作为一名客户经理，  
> 我想要在系统中登记一笔新的宣传物料订单（填写客户名称、物料类型、数量、规格、交付日期、上传参考文件），  
> 以便将客户需求正式记录并推动进入后续流程。

**角色：** 客户经理  
**关联状态：** 无 → 待分派

---

### Scenario: 正常登记订单并提交成功

> **标签：** `@happy-path` `@order-create`

```gherkin
Given 客户经理已登录系统，并且处于"新建订单"页面
When 客户经理填写客户名称为"星辰科技有限公司"、物料类型选择"海报"、数量填写"500"、
     规格填写"A2铜版纸双面彩印"、交付日期选择"2026-11-15"、上传 1 张参考图片，
     并点击"提交订单"按钮
Then ① 页面展示：跳转到"订单详情"页，页面顶部显示订单编号，状态标签显示为"待分派"，
        所有已填写字段均正确回显；
     ② 数据存储：系统中新增一条订单记录，状态为"待分派"，创建人显示为当前客户经理；
     ③ 系统提示：页面右上角弹出"订单提交成功，等待业务负责人分派"的成功提示。
```

---

### Scenario: 必填项为空时提交被拦截

> **标签：** `@edge-input` `@validation`

```gherkin
Given 客户经理已登录系统，并且处于"新建订单"页面
When 客户经理将客户名称留空、物料类型未选择、数量留空、交付日期未选择，
     直接点击"提交订单"按钮
Then ① 页面展示：页面停留在"新建订单"页，客户名称输入框下方显示红色提示"请输入客户名称"，
        物料类型下拉框下方显示红色提示"请选择物料类型"，
        数量输入框下方显示红色提示"请输入数量"，
        交付日期下方显示红色提示"请选择交付日期"；
     ② 数据存储：系统中未新增任何订单记录；
     ③ 系统提示：页面顶部显示红色横幅"请完善必填项后再提交"。
```

---

### Scenario: 重复快速提交导致重复订单

> **标签：** `@edge-state` `@concurrency`

```gherkin
Given 客户经理已登录系统，并且处于"新建订单"页面，
      已完整填写客户名称、物料类型、数量、规格、交付日期并上传参考文件
When 客户经理在 1 秒内连续点击 3 次"提交订单"按钮
Then ① 页面展示：仅跳转到 1 个"订单详情"页，页面上仅显示 1 个订单编号，状态为"待分派"；
     ② 数据存储：系统中仅新增 1 条订单记录，无重复订单；
     ③ 系统提示：首次点击后"提交订单"按钮立即变为禁用状态并显示"提交中..."，
        后续点击无响应，提交成功后显示"订单提交成功"提示。
```

## US-002 · 业务负责人分派订单

**用户故事：**
> 作为一名业务负责人，  
> 我想要查看所有"待分派"状态的订单，并为订单指定一位设计人员，  
> 以便明确任务责任人，启动设计工作。

**角色：** 业务负责人  
**关联状态：** 待分派 → 设计中

---

### Scenario: 正常分派订单给指定设计人员

> **标签：** `@happy-path` `@order-assign`

```gherkin
Given 业务负责人已登录系统，并且处于"待分派订单列表"页，
      列表中存在 1 条编号为 ORD-2026-0001 的"待分派"订单
When 业务负责人点击订单 ORD-2026-0001 的"分派"按钮，
     在弹出的分派窗口中选择设计人员"李明"，并点击"确认分派"按钮
Then ① 页面展示：订单列表中 ORD-2026-0001 的状态由"待分派"变为"设计中"，
        负责人列显示为"李明"，"分派"按钮消失；
     ② 数据存储：订单 ORD-2026-0001 的状态更新为"设计中"，
        设计负责人字段更新为"李明"，分派时间记录为当前时间；
     ③ 系统提示：页面右上角弹出"订单已分派给李明"的成功提示。
```

---

### Scenario: 未选择设计人员就确认分派被拦截

> **标签：** `@edge-input` `@validation`

```gherkin
Given 业务负责人已登录系统，并且处于"待分派订单列表"页，
      列表中存在 1 条编号为 ORD-2026-0002 的"待分派"订单
When 业务负责人点击订单 ORD-2026-0002 的"分派"按钮，
     在弹出的分派窗口中不选择任何设计人员，直接点击"确认分派"按钮
Then ① 页面展示：分派窗口仍然打开，设计人员下拉框下方显示红色提示"请选择设计人员"；
     ② 数据存储：订单 ORD-2026-0002 的状态仍为"待分派"，设计负责人字段为空；
     ③ 系统提示：分派窗口内显示红色小字提示"请先选择设计人员"。
```

---

### Scenario: 订单已被他人分派导致状态冲突

> **标签：** `@edge-state` `@concurrency`

```gherkin
Given 业务负责人 A 和业务负责人 B 均已登录系统，
      两人同时在"待分派订单列表"页查看订单 ORD-2026-0003，状态均显示为"待分派"
When 业务负责人 A 先将订单 ORD-2026-0003 分派给设计人员"李明"，
     随后业务负责人 B 也点击该订单的"分派"按钮并选择设计人员"王芳"确认分派
Then ① 页面展示：业务负责人 B 的页面上分派窗口关闭，
        订单列表中 ORD-2026-0003 的状态显示为"设计中"，负责人显示为"李明"；
     ② 数据存储：订单 ORD-2026-0003 的状态为"设计中"，设计负责人为"李明"，
        未被 B 的操作覆盖；
     ③ 系统提示：业务负责人 B 的页面弹出红色错误提示"该订单已被其他负责人分派，请刷新列表"。
```

## US-003 · 设计人员查看我的订单

**用户故事：**
> 作为一名设计制作人员，  
> 我想要查看分派给我的订单列表及详细需求（含参考文件），  
> 以便准确理解需求并开始设计工作。

**角色：** 设计制作人员  
**关联状态：** 设计中（只读查看）

---

### Scenario: 正常查看分派给自己的订单详情

> **标签：** `@happy-path` `@order-view`

```gherkin
Given 设计人员李明已登录系统，并且处于"我的任务"列表页，
      列表中存在 1 条状态为"设计中"的订单 ORD-2026-0001，负责人为李明
When 设计人员李明点击订单 ORD-2026-0001 的"查看详情"按钮
Then ① 页面展示：跳转到"订单详情"页，页面显示客户名称为"星辰科技有限公司"、
        物料类型为"海报"、数量为"500"、规格为"A2铜版纸双面彩印"、
        交付日期为"2026-11-15"，参考文件区域显示已上传的参考图片缩略图；
     ② 数据存储：系统记录李明在当前时间查看了订单 ORD-2026-0001（用于统计）；
     ③ 系统提示：页面无额外提示，内容正常加载。
```

---

### Scenario: 搜索框输入特殊字符时搜索结果为空

> **标签：** `@edge-input` `@validation`

```gherkin
Given 设计人员李明已登录系统，并且处于"我的任务"列表页，
      列表中存在 2 条分派给李明的订单
When 设计人员李明在订单搜索框中输入 "<script>alert(1)</script>" 并按回车搜索
Then ① 页面展示：列表显示"暂无匹配的订单"，搜索框中保留输入的特殊字符，页面无弹窗；
     ② 数据存储：系统未执行任何异常操作，订单数据无变化；
     ③ 系统提示：列表区域显示"未找到包含该关键词的订单"的空状态提示。
```

---

### Scenario: 已交付的订单不再出现在"我的任务"列表中

> **标签：** `@edge-state` `@order-status`

```gherkin
Given 设计人员李明已登录系统，并且处于"我的任务"列表页，
      列表中存在 1 条状态为"设计中"的订单 ORD-2026-0004
When 业务负责人将订单 ORD-2026-0004 标记为"已交付"，
     设计人员李明刷新"我的任务"列表页
Then ① 页面展示："我的任务"列表中不再显示 ORD-2026-0004，列表数量减 1；
     ② 数据存储：订单 ORD-2026-0004 状态为"已交付"，仍可在"全部订单"中查询到；
     ③ 系统提示：页面无额外提示，列表正常刷新。
```

## US-004 · 设计人员上传设计稿

**用户故事：**
> 作为一名设计制作人员，  
> 我想要为订单上传设计稿并标注版本号，提交后订单状态自动变为"待审核"，  
> 以便将设计成果交付审核并进入下一环节。

**角色：** 设计制作人员  
**关联状态：** 设计中 → 待审核

---

### Scenario: 正常上传第一版设计稿并提交审核

> **标签：** `@happy-path` `@design-upload`

```gherkin
Given 设计人员李明已登录系统，并且处于订单 ORD-2026-0001 的详情页，
      订单状态为"设计中"，当前无任何设计稿版本
When 设计人员李明点击"上传设计稿"按钮，
     选择 1 个 PSD 文件，版本号自动填充为"V1"，
     版本说明填写"初稿完成，整体风格偏科技感"，然后点击"提交审核"按钮
Then ① 页面展示：订单详情页的状态标签由"设计中"变为"待审核"，
        设计稿版本列表新增一条 V1 记录，显示文件名、上传时间、版本说明，
        "上传设计稿"按钮变为禁用状态；
     ② 数据存储：系统新增一条设计稿版本记录，关联订单 ORD-2026-0001，
        版本号为 V1，上传人为李明，订单状态更新为"待审核"；
     ③ 系统提示：页面右上角弹出"设计稿已提交，等待审核"的成功提示。
```

---

### Scenario: 上传文件格式不支持时被拦截

> **标签：** `@edge-input` `@validation`

```gherkin
Given 设计人员李明已登录系统，并且处于订单 ORD-2026-0002 的详情页，
      订单状态为"设计中"
When 设计人员李明点击"上传设计稿"按钮，选择 1 个 .exe 可执行文件并尝试上传
Then ① 页面展示：上传窗口仍打开，文件列表中该文件显示红色叉号和提示文字"不支持的文件格式"，
        "提交审核"按钮保持禁用；
     ② 数据存储：系统未保存该文件，订单状态仍为"设计中"；
     ③ 系统提示：文件条目旁显示"仅支持 PSD、AI、JPG、PNG、PDF 格式"的错误提示。
```

---

### Scenario: 订单已在"待审核"状态时重复上传

> **标签：** `@edge-state` `@order-status`

```gherkin
Given 设计人员李明已登录系统，并且处于订单 ORD-2026-0003 的详情页，
      订单状态为"待审核"，已存在 V1 版本设计稿
When 设计人员李明尝试点击页面上的"上传设计稿"按钮
Then ① 页面展示："上传设计稿"按钮呈灰色禁用状态，点击无响应，
        页面提示区域显示"当前订单处于待审核状态，请等待审核意见后再上传新版本"；
     ② 数据存储：系统未新增任何设计稿版本，订单状态保持"待审核"；
     ③ 系统提示：鼠标悬停在禁用按钮上时，显示 tooltip"待审核状态不可上传新设计稿"。
```

## US-005 · 客户经理提交修改意见

**用户故事：**
> 作为一名客户经理，  
> 我想要查看设计稿并提交文字修改意见，同时可查看历史修改记录，  
> 以便将客户反馈准确传达给设计团队并跟踪迭代过程。

**角色：** 客户经理  
**关联状态：** 待审核 → 修改中

---

### Scenario: 正常提交修改意见并流转到修改中

> **标签：** `@happy-path` `@feedback-submit`

```gherkin
Given 客户经理已登录系统，并且处于订单 ORD-2026-0001 的详情页，
      订单状态为"待审核"，设计稿版本列表中有 V1 版本
When 客户经理查看 V1 设计稿后，在修改意见输入框中填写"主标题字体改为粗体，底部Logo向右移动20px"，
     并点击"提交修改意见"按钮
Then ① 页面展示：订单状态标签由"待审核"变为"修改中"，
        修改记录列表新增一条记录，显示提交人、提交时间、意见内容，
        输入框被清空；
     ② 数据存储：系统新增一条修改意见记录，关联订单 ORD-2026-0001 和 V1 版本，
        提交人为当前客户经理，订单状态更新为"修改中"；
     ③ 系统提示：页面右上角弹出"修改意见已提交，设计人员将尽快处理"的成功提示。
```

---

### Scenario: 修改意见内容为空时提交被拦截

> **标签：** `@edge-input` `@validation`

```gherkin
Given 客户经理已登录系统，并且处于订单 ORD-2026-0002 的详情页，

When 客户经理将修改意见输入框留空，直接点击"提交修改意见"按钮
Then ① 页面展示：页面停留在订单详情页，修改意见输入框下方显示红色提示"请输入修改意见"，
        订单状态仍为"待审核"；
     ② 数据存储：系统未新增修改意见记录，订单状态保持"待审核"；
     ③ 系统提示：输入框下方显示"修改意见不能为空"的红色错误提示。
```

---

### Scenario: 订单已定稿后仍尝试提交修改意见

      订单状态为"已交付"，历史修改记录列表中有多条记录

Then ① 页面展示：修改意见输入框呈灰色禁用状态，无法输入文字，
        "提交修改意见"按钮也为禁用状态；

## US-006 · 设计人员上传新版本设计稿

**用户故事：**
> 作为一名设计制作人员，  
> 我想要查看修改意见并上传新版本设计稿，系统自动保留版本历史，  
> 以便根据反馈迭代设计，且每版改动均可追溯。

**角色：** 设计制作人员  
**关联状态：** 修改中 → 待审核

---

### Scenario: 根据修改意见上传 V2 版本设计稿

> **标签：** `@happy-path` `@design-iteration`

```gherkin
Given 设计人员李明已登录系统，并且处于订单 ORD-2026-0001 的详情页，
      订单状态为"修改中"，存在 V1 版本设计稿及 1 条修改意见
When 设计人员李明查看修改意见后，点击"上传新版本"按钮，
     选择 1 个新的 PSD 文件，版本号自动填充为"V2"，
     版本说明填写"已按意见调整标题字体和Logo位置"，然后点击"提交审核"按钮
Then ① 页面展示：订单状态标签由"修改中"变为"待审核"，
        设计稿版本列表新增 V2 记录并置于顶部，V1 记录下移，
        每条版本记录旁可展开查看对应版本的修改意见；
     ② 数据存储：系统新增一条 V2 版本设计稿记录，关联订单 ORD-2026-0001，
        上传人为李明，订单状态更新为"待审核"，V1 版本记录保留不变；
     ③ 系统提示：页面右上角弹出"V2 版本已提交审核"的成功提示。
```

---

### Scenario: 版本说明超长文字时被截断并提示

> **标签：** `@edge-input` `@validation`

```gherkin
Given 设计人员李明已登录系统，并且处于订单 ORD-2026-0003 的详情页，
      订单状态为"修改中"，存在 V1 版本及 1 条修改意见
When 设计人员李明点击"上传新版本"按钮，选择设计文件后，
     在版本说明输入框中输入 500 个字符（超过 200 字限制），然后点击"提交审核"按钮
Then ① 页面展示：上传窗口仍打开，版本说明输入框下方显示红色提示"版本说明不能超过 200 字"，
        输入框右侧字数统计显示为红色"500/200"；
     ② 数据存储：系统未新增设计稿版本记录，订单状态保持"修改中"；
     ③ 系统提示：输入框下方显示红色错误提示"版本说明超长，请精简至 200 字以内"。
```

> 以便完成一笔订单的全流程闭环并沉淀交付记录。

**角色：** 业务负责人  
**关联状态：** 待审核 → 已交付

### Scenario: 正常确认终稿并标记订单已交付

                │           │

| 已交付 | 仅查看 | 全部角色 |
